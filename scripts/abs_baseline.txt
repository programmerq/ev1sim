# ev1sim ABS regression baseline — headline BTCM-on metrics per scenario.
# Consumed by scripts/abs_regression.sh via `compare_abs_runs.py --check`.
#
# electricsim-commit: 7157b25   (controllers built at this commit; phase counts
#                                and absolute metrics move with the BTCM/PIM/RSA
#                                version, so re-capture when electricsim moves)
# ev1sim: built from the rear-shoe step-integrator change (src/SimApp.cpp
#         ApplyRearEmbBrake passes the physics step) on current main.
# capture method: scripts/run_abs_compare.sh per scenario (electricsim VAT
#                 harness on the wire-table bus), single pass.  The ~ rows hold
#                 that capture's values.  The lock ceilings and phase floors are
#                 ABS-quality targets, not captured values: low_mu and mu_jump
#                 exceed them and split_mu yaws, which is the ABS stand-in's
#                 open retune, so this file fails on those rows until it lands.
#
# Rule shapes (deliberate):
#   - stopping distance: two-sided +/-10% (both directions matter).
#   - time-locked %: UPPER bound only.  Less lock is an improvement, not a
#     regression; the ceiling catches ABS degrading toward the BTCM-off lock.
#   - yaw: bounded.  Near-zero for straight stops; large+preserved for the
#     steering scenario.
#   - phase count: lower bound — confirms the BTCM is actually modulating.
#     It is controller-driven, so not tied tightly to the ev1sim plant.
#
# format: <scenario> <metric_key> <op> <value> [tol_frac]
#   op: ~ (within +/-tol of value, default 0.10) | < | <= | > | >=
